# Architecture

Ibexa DXP architecture is structured in multiple layers connected by APIs.

Ibexa DXP architecture is based on the philosophy to **use APIs** that is maintained in the long term. This **makes upgrades easier and provides lossless couplings** between all parts of the architecture, at the same time improving the migration capabilities of the system.

The structure of an Ibexa DXP app is based on the Symfony framework but content management functions rely on the public PHP API. Other applications integrate with Ibexa DXP via REST API, which also relies on the public PHP API.

![Architecture](https://doc.ibexa.co/en/5.0/administration/img/architecture.png "Architecture")

The architecture of Ibexa DXP is layered and uses clearly defined APIs between the layers.

| Layer                                                                                                                           | Description                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Back office](../../back_office/back_office_configuration/index.md)                        | Back office contains all the necessary parts to run the Ibexa DXP back office interface.                                                                                                            |
| [HTTP Cache](../../../infrastructure_and_maintenance/cache/http_cache/http_cache/index.md)                   | Symfony HTTP cache is used to manage content "view" cache with an expiration model. In addition it is extended by using FOSHttpCache to add several advanced features.                              |
| [Controllers](../../../templating/queries_and_controllers/controllers/index.md)                              | Controllers created by you to read information from a Request object, create and return a Response objects.                                                                                         |
| [Twig templates](../../../templating/twig_function_reference/twig_function_reference/index.md)               | Set of custom and built-in Twig templates. User interfaces are developed with the Twig template engine and query the public PHP API directly.                                                       |
| [REST API v2](../../../api/rest_api/rest_api_usage/rest_api_usage/index.md)                                  | The REST API v2 enables you to interact with an Ibexa DXP installation through the HTTP protocol, following a REST interaction model.                                                               |
| [GraphQL](../../../api/graphql/graphql/index.md)                                                             | GraphQL for Ibexa DXP exposes the domain model using the repository, based on content type groups, content types and field definitions.                                                             |
| [Public PHP API](../../../api/php_api/php_api/index.md)                                                      | Public PHP API exposes the repository which enables you to create, read, update, manage and delete all objects available in Ibexa DXP.                                                              |
| Business Logic                                                                                                                  | The business logic is defined in the kernel. This business logic is exposed to applications via an API. It is used to organize development of the user interface layer.                             |
| SPI                                                                                                                             | Service Provider Interface which defines contracts for implementing various parts of the system, including persistence layer (`SPI\Persistence`), custom field types, custom limitations, and more. |
| [Persistence cache](../../../infrastructure_and_maintenance/cache/persistence_cache/index.md)                | The implementation of SPI\\Persistence that decorates the main backend implementation.                                                                                                              |
| [Search](../../../search/search/index.md)                                                                    | Search API that allows both full-text search and querying the content.                                                                                                                              |
| [SQL Storage Engine](../../../search/search_engines/legacy_search_engine/legacy_search_overview/index.md)    | Legacy search engine is SQL-based and uses Doctrine's database connection.                                                                                                                          |
| [Solr Storage Engine](../../../search/search_engines/solr_search_engine/solr_overview/index.md)              | Transparent drop-in replacement for the SQL-based Legacy search engine.                                                                                                                             |
| [IO](../../../content_management/file_management/file_management/index.md#native-io-handler)                         | The IO API is organized around two types of handlers, both used by the IOService.                                                                                                                   |
| [IO Handler](../../../infrastructure_and_maintenance/clustering/clustering/index.md#dfs-io-handler)                  | The IO Handler manipulates metadata, making up for the potential inconsistency of network-based filesystems.                                                                                        |
| [Recommendations](../../../recommendations/raptor_integration/connector_installation_configuration/index.md) | Recommendation API.                                                                                                                                                                                 |
| [Raptor recommendation connector](../../../recommendations/raptor_integration/raptor_connector/index.md)     | Raptor recommendation connector allows displaying recommendations on the website.                                                                                                                   |
